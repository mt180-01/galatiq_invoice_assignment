# Evaluation: every invoice, two separate runs

Generated by `python scripts/evaluate.py`; do not edit by hand. Both runs process the 20 files in `data/invoices/` (17 distinct invoices; 3 are the same bill sent in two formats, which the duplicate check blocks) from an empty ledger.

* **Rules only**: no model at all (`--offline`).
* **LLM on**: the recorded live Grok run (`docs/live_runs/provided-invoices.cassette.jsonl`) replayed offline: the real model's answers, no network, no key, no cost. To check it yourself: `python main.py --replay-llm docs/live_runs/provided-invoices.cassette.jsonl --invoice_path data/invoices`.

**Two kinds of label, kept apart.** *Brief* is what the assignment itself says should happen to eight invoices (independent of this code). *Label* is the expected outcome for all 17 that the developer wrote while building the system, so it guards against regressions but is **not** an independent test.

## The two runs side by side

* Decisions identical on **17 of 17** invoices.
* The model did not change a single decision on these invoices. That is by design (it can only tighten a decision, and the provided invoices are clear-cut), so what it adds here is a second opinion before each payment (7 paid), plain-English notes (10), vendor emails (4) and document reading where the rules were unsure. Where it changes outcomes is `data/self_correction/` (mistyped item names found by catalogue search), which is not part of this table.
* Latency and cost of the model run are in `docs/live_runs/`; the rules-only run is milliseconds and free.
